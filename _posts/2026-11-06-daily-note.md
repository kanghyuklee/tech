## 쿼리 최적화란 무엇인가요?

쿼리 최적화는 데이터베이스에서 데이터를 조회할 때 성능을 향상시키는 작업을 말해요. 예를 들어, 불필요한 데이터를 조회하거나 비효율적인 조건을 사용하면 응답 시간이 길어질 수 있어요.

**예시:**

```sql
-- 비효율적인 쿼리
SELECT * FROM users WHERE YEAR(created_at) = 2026;
```

이 쿼리는 `created_at` 컬럼의 연도를 추출하여 비교하는데, 인덱스를 활용하지 못해 성능이 저하될 수 있어요.

**최적화 방법:**

```sql
-- 최적화된 쿼리
SELECT * FROM users WHERE created_at >= '2026-01-01' AND created_at < '2027-01-01';
```

이렇게 하면 `created_at` 컬럼에 인덱스를 활용할 수 있어 성능이 향상돼요.

## 인덱스는 왜 중요한가요?

인덱스는 데이터베이스에서 데이터를 빠르게 찾을 수 있도록 도와주는 자료구조예요. 책에서 색인처럼 생각하면 돼요.

**예시:**

```sql
-- 인덱스 생성
CREATE INDEX idx_email ON users(email);
```

이렇게 `email` 컬럼에 인덱스를 생성하면, 해당 컬럼을 조건으로 하는 조회가 빨라져요.

**주의사항:**

인덱스는 조회 성능을 높여주지만, 데이터 삽입, 수정, 삭제 시에는 추가적인 비용이 발생해요. 따라서 필요한 컬럼에만 인덱스를 생성하는 것이 좋아요.

## 트랜잭션 관리란 무엇인가요?

트랜잭션은 데이터베이스에서 하나의 작업 단위를 의미해요. 예를 들어, 은행에서 돈을 이체할 때 출금과 입금이 모두 성공해야만 실제로 돈이 이동하죠. 이러한 작업을 트랜잭션이라고 해요.

**트랜잭션의 특성(ACID):**

- **원자성(Atomicity):** 모든 작업이 성공하거나 모두 실패해야 해요.
- **일관성(Consistency):** 트랜잭션 전후에 데이터베이스가 일관된 상태여야 해요.
- **격리성(Isolation):** 동시 실행되는 트랜잭션이 서로 영향을 미치지 않아야 해요.
- **내구성(Durability):** 트랜잭션이 성공하면 그 결과는 영구적으로 저장돼야 해요.

**예시:**

```sql
-- 트랜잭션 시작
START TRANSACTION;

-- 출금
UPDATE accounts SET balance = balance - 100 WHERE account_id = 1;

-- 입금
UPDATE accounts SET balance = balance + 100 WHERE account_id = 2;

-- 트랜잭션 커밋
COMMIT;
```

이렇게 하면 출금과 입금이 모두 성공하거나 모두 실패하게 돼요.

## 운영 시 고려사항은 무엇인가요?

운영 환경에서는 데이터베이스의 안정성과 성능을 지속적으로 모니터링해야 해요.

**모니터링 지표:**

- **응답 시간:** 쿼리 실행 시간이 길어지면 성능 저하를 의미해요.
- **CPU 사용률:** 과도한 CPU 사용은 서버 부하를 나타내요.
- **메모리 사용량:** 메모리 부족은 성능 저하를 초래할 수 있어요.

**최적화 방법:**

- **인덱스 최적화:** 불필요한 인덱스를 제거하고 필요한 인덱스를 추가해요.
- **쿼리 최적화:** 실행 계획을 분석하여 비효율적인 쿼리를 개선해요.
- **하드웨어 확장:** 서버의 CPU, 메모리, 스토리지 용량을 늘려요.

이러한 방법들을 통해 데이터베이스의 성능을 유지하고 향상시킬 수 있어요.
