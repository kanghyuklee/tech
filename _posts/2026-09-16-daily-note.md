로그인 화면을 조금 수정했다고 해볼게요. 아이디와 비밀번호를 넣고, 로그인이 되는지 확인하고, 잘못된 비밀번호도 입력해봐야 하죠. 배포할 때마다 이 과정을 반복한다면 슬슬 이런 생각이 들 수 있어요. “매번 똑같이 확인하는 부분은 자동으로 돌릴 수 없을까?”

테스트 자동화는 이런 반복 작업에서 시작하면 좋아요. 처음부터 모든 테스트를 코드로 바꾸려고 하기보다는, 자주 확인하면서도 결과가 분명한 기능 하나를 골라보세요. 이 글에서는 로그인 테스트를 예로 들어 작은 자동화를 어떻게 시작할지 살펴볼게요.

## 자주 확인하는 기능 하나부터 골라보세요

처음 자동화할 대상을 고를 때는 세 가지를 생각해보면 좋아요. 얼마나 자주 확인하는지, 문제가 생기면 사용자에게 얼마나 큰 영향을 주는지, 기대하는 결과를 명확하게 적을 수 있는지예요.

예를 들어 “올바른 계정으로 로그인하면 환영 문구가 나타난다”는 결과를 비교적 구체적으로 정할 수 있죠. 반면 “화면이 쓰기 편하다”는 기준은 이것만으로 판단하기 어려워요. 자동화가 맡을 부분과 사람이 직접 살펴볼 부분을 나눠두면 시작이 한결 수월해져요.

반복 작업을 줄일 수 있다고 해서 자동화가 늘 시간을 아껴주는 건 아니에요. 화면이 바뀔 때마다 테스트도 고쳐야 하거든요. 처음에는 작은 범위를 안정적으로 돌려보고, 유지하는 데 드는 시간을 보면서 넓혀가는 편이 좋아요.

## 도구는 확인하려는 대상에 맞춰 고르면 돼요

도구 이름부터 외우기보다는 무엇을 확인할지 먼저 정해보세요. 브라우저를 열어 로그인 흐름을 따라가고 싶다면 Selenium 같은 브라우저 자동화 도구를 살펴볼 수 있어요. JavaScript 함수의 반환값을 확인하려는 경우라면 브라우저 전체를 실행할 필요가 없을 수도 있죠.

같은 로그인 기능이어도 입력값 검증과 실제 화면에서의 로그인 흐름은 확인하는 범위가 달라요. 팀에서 이미 사용하는 언어와 테스트 도구도 함께 고려해보세요. 새 도구를 도입하는 것보다 기존 테스트에 작은 사례를 추가하는 쪽이 더 간단할 수 있어요.

## 로그인 테스트를 코드로 옮겨볼게요

아래는 Python과 Selenium으로 로그인 흐름을 표현한 예제예요. **실제 서비스에서 실행해 검증한 코드는 아니에요.** `example.com/login`은 설명용 주소이므로 테스트 환경의 URL로 바꿔야 해요. 입력란의 `name` 속성과 로그인 뒤에 나오는 문구도 서비스에 맞춰 수정해주세요.

Selenium에서 요소를 찾을 때는 `find_element`에 `By.NAME`처럼 찾는 기준을 전달할 수 있어요. 자세한 사용법은 [Selenium 공식 문서](https://www.selenium.dev/documentation/webdriver/elements/finders/)에서 확인할 수 있어요.

```python
import os
from selenium import webdriver
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait

# 테스트 전용 계정 정보를 환경변수로 준비해주세요.
test_user = os.environ["TEST_USER"]
test_password = os.environ["TEST_PASSWORD"]

driver = webdriver.Chrome()
try:
    # 실제 테스트 환경 주소로 바꿔주세요.
    driver.get("https://example.com/login")
    driver.find_element(By.NAME, "username").send_keys(test_user)
    driver.find_element(By.NAME, "password").send_keys(test_password)
    driver.find_element(By.NAME, "login").click()

    # 서비스에서 실제로 보여주는 성공 문구에 맞춰주세요.
    WebDriverWait(driver, 10).until(
        lambda browser: f"Welcome, {test_user}" in browser.page_source
    )
finally:
    driver.quit()
```

흐름은 단순해요. 로그인 페이지로 이동한 뒤 계정 정보를 넣고 버튼을 눌러요. 그다음 성공 문구가 페이지에 나타나는지 기다리죠. 테스트 중 오류가 나더라도 브라우저를 닫을 수 있도록 종료 코드는 `finally`에 넣었어요.

여기서 성공 문구를 찾는 조건은 출발점이에요. 실제 서비스에서는 로그인한 사용자 이름이 화면에 보이는지, 로그인한 사용자만 접근할 수 있는 화면에 진입했는지처럼 더 분명한 기준을 정해보세요. 페이지 소스에 문구가 있다는 사실만으로는 화면에 제대로 표시됐는지까지 알 수 없으니까요.

## 한 번 성공한 다음에는 실패하는 경우도 확인해봐요

테스트가 초록색으로 끝났다면, 잘못된 비밀번호를 넣었을 때도 성공으로 처리되는 건 아닌지 확인해보세요. 오류를 놓치는 테스트는 계속 통과하더라도 도움이 되지 않아요.

로컬에서 흐름을 확인했다면 CI에 연결해볼 수 있어요. CI는 코드 변경이 올라올 때 빌드나 테스트를 자동으로 실행하는 환경이에요. 다만 테스트 계정과 데이터, 접속 주소가 달라지면 로컬과 결과가 달라질 수 있어요. 실패했을 때 어떤 조건에서 실행됐는지 알 수 있게 기록을 남겨두면 원인을 찾기 쉬워져요.

처음 만든 테스트라면 이 정도를 직접 확인해보세요.

- [ ] 정상 계정으로 로그인했을 때 기대한 결과가 나와요.
- [ ] 잘못된 계정 정보로는 성공 조건을 통과하지 못해요.
- [ ] 반복 실행해도 이전 실행의 데이터 때문에 결과가 달라지지 않아요.
- [ ] 실패한 단계와 원인을 로그에서 찾아볼 수 있어요.

오늘은 자주 확인하는 기능 하나만 골라도 충분해요. 그 테스트를 팀에서 믿고 사용할 수 있게 다듬다 보면, 다음에 어떤 작업을 자동화하면 좋을지도 조금씩 보일 거예요.
